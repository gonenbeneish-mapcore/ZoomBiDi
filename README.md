# ZoomBiDi

<img src="assets/ZoomBiDi.ico" width="64" alt="ZoomBiDi icon">

Bidirectional (Hebrew + English) text fix for Zoom chat.

Zoom's chat box gets confused when a line mixes Hebrew (right-to-left) and English (left-to-right): the caret
jumps around and words appear in the wrong order. The manual fix is to type the invisible
**U+2067 RIGHT-TO-LEFT ISOLATE** character at the start of each line.

This small tray app does that for you. It runs in the background and, **only while Zoom is the active window**,
watches what you type:

* When the first letter you type on a line is Hebrew (or Arabic), and the caret really is at the start of a
  line in a Zoom message box, it inserts U+2067 right before that letter.
* Lines that start in English are left alone. If the line already has a direction mark, nothing is added.
* Digits, spaces and punctuation before the first letter (`12 - שלום`) are fine. The mark goes in before the Hebrew word.
* Only Zoom's chat input is affected (its accessible name contains "Message"). Search boxes and other fields are not.

## Run

```
publish\ZoomBiDi.exe
```

Needs the .NET 8 (or newer) Desktop Runtime. A blue **Aא** icon appears in the system tray:

* **Left-click**: pause / resume (grey = paused)
* **Right-click**: menu
  * *Only when the line starts in Hebrew* (default) / *At the start of every line*
  * *Start with Windows*: adds/removes an entry under `HKCU\...\CurrentVersion\Run`
  * *Debug log* / *Open log*: logs each decision to `%APPDATA%\ZoomBiDi\log.txt`
  * *Open settings file*
  * *Exit*

## Settings

`%APPDATA%\ZoomBiDi\settings.json` (restart the app after editing):

| Setting | Default | Meaning |
|---|---|---|
| `Mode` | `RtlFirst` | `RtlFirst` = only lines that start in Hebrew; `Always` = every line |
| `MarkerHex` | `2067` | Code point to insert (e.g. `200F` for RLM) |
| `ProcessNames` | `["Zoom"]` | Which processes count as Zoom |
| `ChatNamePattern` | `message` | Regex matched against the focused text box's accessible name |
| `UiaTimeoutMs` | `250` | Give up (type without the mark) if the check takes longer |
| `DebugLog` | `false` | Write decisions to `log.txt` |

## How it works

* A low-level keyboard hook (on its own thread) translates each key with the active keyboard layout.
* UI Automation is consulted only for the **first letter after something that could have started a new line**:
  Enter, Backspace, arrows, Home/End, clicks, shortcuts (Ctrl+V…), or switching windows. Ordinary typing never
  waits on anything.
* For that letter, the key is held for a few milliseconds while UI Automation reads the focused element: is it
  a Zoom message box, and is there only neutral text between the start of the line and the caret? Then the held
  keys are replayed, with U+2067 in front if needed. Keys typed during the check are held and replayed in order.
* The hook never blocks. If UI Automation is slow, the keys are released unchanged after `UiaTimeoutMs`.

## Build

The icons in `assets\` are generated by `tools\MakeIcon.ps1` (it also writes `assets\icon-preview.png`).

```
dotnet publish ZoomBiDi.csproj -c Release -o publish -p:PublishSingleFile=true -p:SelfContained=false -r win-x64
```

## Test

`test\testpage.html` is a Chromium contenteditable box labelled like Zoom's. `test\TypeHarness.ps1` types Hebrew,
English and mixed sentences into it, with the real Hebrew/English keyboard layouts (`-Mode layout`) or as
injected characters (`-Mode unicode`), and checks exactly where U+2067 landed. To run it, start the app with a
settings file that has `"ProcessNames": ["msedge"]` and `"ProcessInjectedInput": true`, open the page in Edge, then:

```
powershell -ExecutionPolicy Bypass -Command "& .\test\TypeHarness.ps1 -Mode layout"
```

The harness stops if the test page loses focus, so it never types into another window.
